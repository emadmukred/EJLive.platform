# EJLIVE.PLATFORM

Distributed ATM electronic-journal (EJ) capture, archive, correlation and remote-operations platform.
**.NET 8 · Windows · Windows Forms only · client–server · no web tier.**

## Layout

```

EJLive.Platform.slnx        same graph, new solution format (VS 17.13+ / SDK 9.0.2xx+)

                              EnableDefaultCompileItems=false (every compile map is explicit)
src/EJLive.{Shared,Core,Business,Application,...}
src/_reference/               demoted corpus: never compiled, always browsable
                              orphan-projects/ exact-duplicates/ vs-copies/ uncompiled/
                              csproj-shells/ xaml-legacy/ corrupted/
tools/inventory/              ledger generators (12 artefacts) + activation ledger
tools/gates/                  40-rule static gate (+ run-gate.ps1)
tools/build, tools/package    build.ps1, package.bat (3 payload zips)
```

`src/_reference/` holds 237 files / 724 k lines of legacy source. It is evidence, not
source of truth: nothing in a runtime project may reference it (`ARCH-3`), and `EJLive.LegacyReference`
links it read-only so it stays navigable in Visual Studio.

## Build, test, package (Windows)

```powershell
powershell tools/build/build.ps1 -Configuration Release -WithTests -WithGate
cmd /c tools\package\package.bat Release          # -> tools/package/dist/*.zip
```

```
dotnet build EJLive.Platform.sln -c Release -m:1 /p:BuildInParallel=false
dotnet test  src/EJLive.Tests/EJLive.Tests.csproj -c Release --no-build      # 371 cases
dotnet run   --project src/EJLive.Verification/EJLive.Verification.csproj -c Release --no-build  # 23 probes
```

## Non-negotiables

Windows Forms only (no WPF/web/external UI framework) · one journal parser per vendor ·
no `unsafe` and no weak hash on a security path · ledgers regenerate per push ·
a rule is never weakened to make CI pass — a violation is fixed or named in `docs/DEBT-LEDGER.md`.
