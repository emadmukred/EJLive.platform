## Incoming rules (auto-applied to every upload)

Three binding documents and a toolchain apply the rules automatically on every
push and pre-commit:

| document | role |
|---|---|
| [`docs/incoming-rules/00_CHANGELOG_Corrections.md`](docs/incoming-rules/00_CHANGELOG_Corrections.md) | every correction applied to the repo, its finding, its fix, its current status |
| [`docs/incoming-rules/01_eJLIVE_Architecture_Analysis_Prompt.md`](docs/incoming-rules/01_eJLIVE_Architecture_Analysis_Prompt.md) | architectural rules (A–K: project topology, compile maps, type ownership, wire protocol, data layer, UI, security, concurrency, patterns, waves, acceptance) |
| [`docs/incoming-rules/02_eJLIVE_Coding_Implementation_Prompt.md`](docs/incoming-rules/02_eJLIVE_Coding_Implementation_Prompt.md) | implementation rules (K–T: file shape, SQL, parsing, network, observability, code patterns, anti-patterns, language, tests, definition of done) |

The toolchain lives at `tools/incoming/incoming_rules.py`. CI runs it via
`.github/workflows/incoming-rules.yml` on every push and pull request; the
local pre-commit hook (`tools/hooks/pre-commit`) runs the same checks so a
violation never reaches GitHub.

Run it locally:

```bash
python3 tools/incoming/incoming_rules.py --upload src/ --check-architecture
python3 tools/incoming/incoming_rules.py --upload src/ --check-implementation
python3 tools/incoming/incoming_rules.py --upload src/ --check-changelog
```

See [`docs/incoming-rules/README.md`](docs/incoming-rules/README.md) for the
full workflow, exit codes, and how to add a new rule.

no `unsafe` and no weak hash on a security path · ledgers regenerate per push ·
